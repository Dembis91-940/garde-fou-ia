# Templates 6 et 7 — Check-lists

> **Comment utiliser ces templates** : imprimez ou dupliquez ces check-lists dans votre outil de suivi (tableur, drive, Notion). Une case ne se coche que lorsqu'elle est réellement faite — jamais « pour plus tard ». Chaque case cochée est datée et signée par la personne qui l'a vérifiée.

---

# Template 6 — Check-list avant déploiement

*À passer pour CHAQUE agent, avant sa mise en production. Aucun point ne doit rester vide.*

| # | Point de contrôle | Fait ? | Date | Vérifié par |
|---|---|---|---|---|
| 1 | **Mission écrite** : l'agent a une mission unique décrite en une phrase, validée par un responsable | ☐ | | |
| 2 | **Registre** : l'agent est inscrit au registre (nom, mission, outils, responsable, date de revue) | ☐ | | |
| 3 | **Compte dédié** : l'agent utilise un compte dédié, jamais un compte humain partagé | ☐ | | |
| 4 | **Moindre privilège** : chaque accès est listé et justifié ; pas d'admin, pas de boîte partagée | ☐ | | |
| 5 | **Données interdites** : liste écrite et datée ; barrières techniques en place (accès, filtres) | ☐ | | |
| 6 | **Prompt sécurisé** : prompt versionné (modèle du pack), consignes de refus et de signalement incluses | ☐ | | |
| 7 | **Validation humaine** : actions sensibles bloquées, seuils définis, validation testée réellement | ☐ | | |
| 8 | **Journal** : journalisation activée, champs complets, traces non modifiables par l'agent | ☐ | | |
| 9 | **Budget** : plafond par tâche, budget mensuel, alerte à 80 %, coupe-circuit opérationnel | ☐ | | |
| 10 | **Sortie d'incident** : procédure remplie, kill switch testé, rôles connus de tous | ☐ | | |
| 11 | **Revue programmée** : date de première revue mensuelle fixée, responsable désigné | ☐ | | |
| 12 | **Test de refus** : on a demandé à l'agent une donnée interdite et une action hors périmètre — il a refusé et signalé | ☐ | | |
| 13 | **Test d'injection** : on a envoyé à l'agent un message contenant une instruction cachée — il ne l'a pas exécutée | ☐ | | |
